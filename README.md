# PixelPacker — depthwise/pointwise CNN accelerator with on-chip VQ on Zynq-7000

An FPGA accelerator for depthwise-separable convolution on the Zynq-7020
(`xc7z020clg484-1`, ZC702), with product-quantisation (VQ) search running on the
same pointwise engine, and an rANS entropy stage on the Cortex-A9.

- **PL:** a fused depthwise (DW) engine and a pixel-major pointwise (PW) engine,
  AXI-Stream fed by two AXI DMAs, at 100 MHz. The PW engine also performs the VQ
  codebook search (M=4, K=64, Dm=16), so VQ costs no extra DSPs. The design uses
  all 220 DSP48E1 on the device.
- **PS:** a bare-metal driver and harness (`Final_code_2/`) that runs the
  pipeline, drives VQ, codes the indices with a divide-free rANS coder, and logs
  board power over PMBus.

> **Status: research code for an unpublished paper.** Performance figures were
> taken with synthetic weights. The rANS coder has **not** been checked for
> byte-identical output against the reference implementation. See
> [Status and caveats](#status-and-caveats).

## Building

### Hardware

Open `Zynq.xpr` in Vivado 2020.2. The IP repository paths must include this
repo's `Zynq.srcs` and the external `dw_fused_axi` IP repository (see *Known
gaps* below). After editing any RTL, regenerate before you build, or the build
reuses a stale cached copy of the IP:

```tcl
update_ip_catalog -rebuild
upgrade_ip [get_ips -filter {IS_LOCKED == 1}]
reset_target all [get_files hw.bd]
generate_target all [get_files hw.bd]
reset_run synth_1
launch_runs impl_1 -to_step write_bitstream
```

Then export the hardware (`.xsa`) and point `Final_2/vitis-comp.json` at it.

### Software

In Vitis, rebuild the `Final_2` platform component first, then the
`Final_code_2` application. Rebuilding only the application leaves it compiled
against the old platform.

**Program the FPGA every time the bitstream changes.** The PL keeps the last
bitstream loaded into it. The Vitis launch configuration (`Final_code_2/_ide/launch.json`,
IDE-local and not versioned) programs from
`Zynq.runs/impl_1/hw_wrapper.bit`, not from the XSA.

At bring-up the harness checks which bitstream is loaded
(`vq_pw_pl_probe_guard()`) and prints the result.

## Testing

```bash
cd Final_code_2/test
XILINX_VIVADO=/path/to/Vivado/2020.2 ./run_vq_tests.sh --rtl
```

This runs the VQ suite under both quantiser profiles (deployed M=4/K=64/Dm=16
and legacy M=8/K=16/Dm=8): golden model, driver programming, range-coder
geometry, RTL benches, the configuration guard and the rANS tests. All 16 host
checks should pass. Leave out `--rtl` to skip the simulator.

The rANS encoder has two versions: the divide-free one (used on the board,
because the A9 has no hardware divide) and a divide-based reference.
`rans_recip_test` checks that both produce identical bytes. Run it after any
change to the encoder.

## Status and caveats

- **Weights are synthetic.** No accelerator output has been compared against a
  software reference.
- **The rANS coder is not validated against the reference.** The spec is
  `RANS_GUIDE.md` + `CONTEXT_CODEC.md`, both external and not in this repo.
  Byte-identical output against the
  reference is the acceptance test and has not been met.
  `rans_stage3_test` needs the reference's `rom.bin`, `slots.bin`, `idx.bin` and
  `payload.bin`, which are not in this repo. The k→id map and context tables in
  `rans_edge.c` are fitted at boot. Timings measured with them are real, but the
  payload sizes are not compression rates.
- **Every number in `results/` says where it came from**: measured on the board,
  a Vivado 2020.2 report on `xc7z020clg484-1`, simulated, or modelled. Keep
  that label on any number you quote. `model/service_model.py` is frozen.
  Differences between it and measurement are reported as findings, not fitted.

## Known gaps

- **External IP.** The `dw_fused_axi` IP definition lives outside this repo, in
  a separate IP repository. The block design will not open without it.
- **Machine-specific paths.** `Zynq.xpr`, several Tcl scripts, the `.rpt` files
  and `CLAUDE.md` contain absolute Windows paths from the original machine.
  Change them for your setup.
- **Build outputs are not checked in.** `.xsa`, `.bit`, `Zynq.runs/`,
  `Zynq.gen/` and the Vitis `build/` and `export/` directories are regenerated
  by the build.

`CLAUDE.md` holds the detailed working notes for this project: toolchain traps,
the rebuild procedure, and the current state of the VQ and rANS work.
